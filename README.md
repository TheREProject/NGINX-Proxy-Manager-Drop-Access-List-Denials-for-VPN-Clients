# NGINX Proxy Manager: Drop Access-List Denials (403 → 444)

| | |
|---|---|
| **Platform** | TrueNAS SCALE (NGINX Proxy Manager app) |
| **Scope** | Global: every proxy host |
| **Change type** | Standard, low risk, reversible in under 2 minutes |
| **Version** | 1.1 (corrections listed in the change log at the end) |

## 1. Objective

When an IP-based Access List denies a client, close the connection with NGINX's special code **444** instead of showing an HTTP **403 Forbidden** page. The setting is applied once, globally, so no proxy host needs its own configuration.

## 2. Context

This change is the last layer of the lab's remote-access controls for WireGuard VPN clients:

```
VPN client ──WireGuard──> OPNsense ──route──> internal DNS resolver (DNS rewrites)
                              │
                              └── direct IP:port to services ──> BLOCKED (firewall)
                              └── https://<name> ──> NGINX Proxy Manager :443
                                                        │
                                       Access List "LAN only" ──deny──> 444 (this change)
                                                        │
                                                      allow ──> backend service
```

The firewall can't distinguish services behind the reverse proxy, because every hostname shares the same IP and port 443. So the proxy itself enforces access, using IP-based Access Lists. This works because VPN traffic is **routed, not NATed**: NGINX sees each client's real tunnel IP.

## 3. Where the file lives

NPM includes custom files only from this path **inside the container**:

```
/data/nginx/custom/server_proxy.conf
```

> ⚠️ The directory is `/data/nginx/custom/`. A folder with a similar name elsewhere (for example `custom_nginx/`) is **not read** by NPM.

On TrueNAS, the container's `/data` directory is stored on a host dataset. To find the host path that maps to it, run:

```bash
sudo docker ps                       # find the NPM container name
sudo docker inspect <npm_container> \
  --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
```

The host file is then `<host path mapped to /data>/nginx/custom/server_proxy.conf`.

To confirm NGINX includes the file:

```bash
sudo docker exec -it <npm_container> sh -c "nginx -T 2>&1 | grep -n 'server_proxy'"
```

Expected (NPM may show the name as `server_proxy[.]conf`, which lets NGINX skip the file without an error if it's missing):

```nginx
include /data/nginx/custom/server_proxy.conf;
```

## 4. Implementation

Run these inside the container (`sudo docker exec -it <npm_container> sh`), or edit the host path from section 3.

```bash
mkdir -p /data/nginx/custom
vi /data/nginx/custom/server_proxy.conf
```

File contents:

```nginx
# Access List denials: close the connection instead of returning 403.
# Applies only to 403s generated by NGINX itself (Access Lists).
# Backend applications' own 403 responses pass through unchanged.
error_page 403 = @close_403;

location @close_403 {
    return 444;   # close the connection with no HTTP response
}
```

> Do **not** add `proxy_intercept_errors on;`. Access List denials are generated by NGINX, so `error_page` catches them without it. With it enabled, legitimate 403s from backend apps (for example, a logged-in user hitting a permission error) would also turn into dropped connections.

## 5. Validate and apply

```bash
nginx -t
```

Expected:

```text
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

Only if the test passes:

```bash
nginx -s reload
```

If it fails, don't reload. Fix the line it reports first.

## 6. Testing

Use `--resolve` so the test doesn't depend on DNS:

```bash
curl -kv --resolve app.example.lan:443:<PROXY_IP> https://app.example.lan/
```

| Test | From | Expected |
|---|---|---|
| Denied client | VPN client (not in the Access List) | `curl: (52) Empty reply from server` |
| Allowed client | LAN client in the Access List | Normal page (`HTTP/2 200` or the app's usual response) |
| Unrestricted host | VPN client, to a host with no Access List | Normal page |
| Backend 403 (optional) | Allowed client, to a page the app itself forbids | The app's own 403, not a dropped connection |

## 7. Scope and limitations

- Applies to every proxy host whose server block includes `server_proxy.conf`, both existing and new.
- Access Lists are unchanged. **New proxy hosts default to "Publicly Accessible,"** so assign the right Access List to each new host (this is on the maintenance checklist).
- Only NGINX-generated 403s are affected. Other status codes, and backend responses, are unchanged.
- 444 is an NGINX-specific code: the connection closes with no HTTP response.
- **HTTPS limitation:** the TLS handshake finishes before the 444 is sent. A denied client still receives the site's certificate, so it learns the hostname exists but gets no content. This adds concealment, not stronger security; the Access List is what enforces access.
- The file must live on persistent app storage (the dataset mapped to `/data`) so it survives redeploying or replacing the container. It is included in lab backups.

## 8. Rollback

```bash
mv /data/nginx/custom/server_proxy.conf /data/nginx/custom/server_proxy.conf.disabled
nginx -t && nginx -s reload
```

Repeat the denied-client test. It should return `403 Forbidden` again.

## 9. Summary

| Parameter | Value |
|---|---|
| File | `/data/nginx/custom/server_proxy.conf` (inside the container) |
| Directive | `error_page 403 = @close_403;` → `return 444;` |
| Result | Access List denials close the connection with no response |
| Backend 403s | Unchanged |
| Per-host changes | None |
| Rollback time | Under 2 minutes |
